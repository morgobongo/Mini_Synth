# Modifications from the Base Scout Model

Summary of all changes made to the OpenSCAD files to adapt the project from the original "Scout" synthesizer, along with corresponding code excerpts.

## 1. Enclosure Modifications
**File:** [`openscad/enclosure.scad`](file:///Users/morgo/Desktop/oskitone/scout/openscad/enclosure.scad)

- **Activation of hidden elements**: The speaker and LED components were uncommented to be integrated into the enclosure.
```openscad
// File: openscad/enclosure.scad
// Uncommented lines:

_led_exposure(cavity = false);
```

- **Removal or customization of branding/synth name**: The text branding on the enclosure is generated by the `_branding()` module. 
To remove it entirely, the `_branding();` call is simply commented out.
If you prefer to add a custom name, you can uncomment `_branding();` and modify it to only display your custom text by replacing "SCOUT" and commenting out the second call (which loads the default Oskitone SVG logo):

```openscad
// File: openscad/enclosure.scad
// Inside module _branding(debug = false):

        // 1. Model Name: Change "SCOUT" to your custom synth name
        enclosure_engraving(
            string = "MY SYNTH", // <-- Changed from "SCOUT"
            size = model_length,
            center = false,
            position = [
                branding_position.x - model_length * .075, // HACK: fix alignment
                branding_position.y
            ],
            quick_preview = quick_preview,
            enclosure_height = dimensions.z
        );

        // 2. Maker Name: Comment this entirely to remove the Oskitone SVG logo
        /*
        enclosure_engraving(
            size = make_length,
            center = false,
            ...
        );
        */
```

- **Addition of new holes/buttons**: Two new cylinders were modeled on top of the enclosure (Octave and Mode). They were placed relative to the volume knob (`knob_position`), offset by 24.5 and 29.5 perfboard units to the left, and 2 units up.
```openscad
// File: openscad/enclosure.scad
// First new button (Octave)
translate([
    knob_position.x - (24.5 * 2.54), 
    knob_position.y + (2 * 2.54), 
    dimensions.z - 20
]) {
    cylinder(d=8, h=40, $fn=32);
}

// Second new button (Mode)
translate([
    knob_position.x - (29.5 * 2.54), 
    knob_position.y + (2 * 2.54), 
    dimensions.z - 20
]) {
    cylinder(d=8, h=40, $fn=32);
}
```

## 2. PCB Fixtures Modifications
**File:** [`openscad/pcb_fixtures.scad`](file:///Users/morgo/Desktop/oskitone/scout/openscad/pcb_fixtures.scad)

- **Back support pillars (`_back_stools`)**: 
The right back support beam was moved to fall exactly below the potentiometer. The left beam was repositioned symmetrically.
```openscad
// File: openscad/pcb_fixtures.scad
// Replacement of position calculation relative to the potentiometer
module _back_stools(size = PCB_STOOL_DIAMETER) {
    right_x = PCB_POT_POSITION.x;
    left_x = PCB_WIDTH - PCB_POT_POSITION.x;
    y = PCB_POT_POSITION.y;

    for (position = [[left_x, y], [right_x, y]]) { ... }
}
```

- **Button support rail (`_button_rail`)**: 
The long rail supporting the buttons was shifted on the Y-axis to move it away from the screw holes, and its width was increased from 3mm to 5mm (extending towards the front to keep the back edge aligned).
```openscad
// File: openscad/pcb_fixtures.scad
// Width increased to 5mm, expanding forward:
        translate([
            pcb_position.x,
            // The old length was 3 (hence +1.5 for the back edge).
            // We expand forward (- length) to keep the back edge in its original shifted place.
            pcb_position.y + PCB_BUTTON_POSITIONS[0].y + 2.54 * 1.5 + 1.5 - length,
            z
        ]) {
```

- **Removal of the front-left rectangular beam (`_corners`)**: 
The left corner reinforcement beam, which was no longer used, was removed from the corners array.
```openscad
// File: openscad/pcb_fixtures.scad
// Before: corner_xs = [-offset, PCB_WIDTH + offset - corner_size];
// After:
corner_xs = [PCB_WIDTH + offset - corner_size];
```

- **Reactivation of PCB support posts**: 
The original PCB support posts (`pcb_post_hole_positions`), located next to the screw holes, were reactivated by passing the parameter down to `pcb_mounting_columns`.
```openscad
// File: openscad/pcb_fixtures.scad
// Before: pcb_post_hole_positions = [], 
// After:
        pcb_post_hole_positions = pcb_post_hole_positions,
```

## 3. PCB Parameters


- **Switch position**: The power switch was shifted towards the back of the synth by changing its Y nudge to `2.54` (1 perfboard hole further back compared to original).

- **Potentiometer position**: The volume potentiometer was shifted away from the keys (towards the back) by changing its Y nudge to add `2.54`.
```openscad
// File: openscad/scout_pcb.scad
```

## 6. Custom Accessories

- **Tactile Button (`custom_button_hole_4mm.scad`)**: A custom "top hat" button was designed for the Mode and Octave switches.
  - Top diameter: `7.6mm` (for clearance in the `8mm` enclosure hole).
  - Top height: `5mm`, featuring a rounded edge (`rotate_extrude` with `r_corner=1.2`).
  - Base diameter: `12mm` to retain the button inside the enclosure.
  - Base thickness: `6mm`.
  - Switch hole: A `4mm` diameter, `2mm` deep hole is subtracted from the bottom to tightly fit a standard `6x6x7 mm` tactile switch. *(Note: After testing, the 4mm diameter works best compared to the original 3.5mm)*.
  - *Alternative Version (`custom_button_flat.scad`)*: A flat version with no hole and a reduced base thickness of `4mm` is also available.

- **Button Adapters (`button_adapter.scad`)**: A utility file to print an array of 20 small `4x4x1 mm` square spacers. This is used because the required tactile switch is `6x6x6 mm`, but using this `1mm` adapter glued under the button allows for the use of a more common `6x6x5 mm` switch instead.

## 7. Script Modifications

- **STL Generation Script (`make_stls.sh`)**: The script was modified to name output directories and files using the current date and time (`YYYY-MM-DD_HHhMMmSSs`) instead of the latest git commit hash. This makes it easier to track different versions exported during development.
